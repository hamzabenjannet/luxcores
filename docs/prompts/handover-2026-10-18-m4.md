# Handover: Placement Fix and M4 (Creeps)

Describes the state after the commits of this session: the placement test and Godot fix, the M4 sim (`fa69b77`), the web client M4 controls, and the Godot M4 client. `docs/HANDOVER.md` holds the live status; this file holds what was decided and checked.

## What Changed

- **Placement.** The sim already refused a second building on a taken tile, and `test/placement.test.js` now pins it (same tick, later, every kind, recycling, Core, blockers, vents, both teams). The bug the owner saw was in Godot: in build mode a tap near an existing building snapped onto it, so a neighbouring tile could not be chosen. Build taps now go exactly where the finger lands. A live Godot test taps by pixel to cover it.
- **M4 sim.** `src/sim/creeps.js`, `systems/production.js`, creep steering in `systems/behavior.js`, creep attacks in `systems/combat.js`. The hash gained groups, orders, waypoints and `groupId`, so the four golden replays were re-recorded (`SPEC_VERSION` stays 0.10.0 by the owners' exception). New goldens: `bots-seed-3-victory` (a creep rush ends a match at tick 2142).
- **Bot.** The fourth rotation slot orders a group of 5 at its newest barracks, limited to 25 creeps alive or queued and 2 waiting orders per barracks.
- **Protocol.** Snapshots carry `groups`, `orders`, `groupId` and each entity's `waypoints`. `cancelQueue` takes an `orderId` (an `index` still works), because the queue shifts when a group finishes.
- **Clients.** The web and Godot clients order creeps, show the queue, select groups, split, merge, set paths and draw routes. The shared parity fixture grew by `mixFor`, `queueLines`, `groupActions` and the path and merge taps.

## Verified

Counts are in `docs/HANDOVER.md` (M4 validation). Highlights:

- Chromium prints the same hash as Node for a bot match with creeps, A* and collisions at tick 5000 (`8c7b7b76`).
- A 30-seed bot soak passes with equal hashes between two runs.
- The web UI test (order, cancel, split, merge, path) passed in three consecutive runs, and so did the Godot live test (41 checks). A fixture screenshot shows the route overlay.
- The first versions of the web UI test were flaky for real reasons, and I fixed each one. A tap that took more than 500 ms between handler calls was not a tap, so taps now use event time stamps. Taps outside the 32-tile viewport landed off screen. Cancelling by queue index hit a stale row, so it now goes by order id.

## Decisions I Made Without Asking

- Creeps attack Cores, buildings, creeps and heroes, never blockers. They keep a target until it dies or leaves sight.
- A barracks in its recycle channel stops producing. Recycling refunds queued orders and loses held groups.
- The default route is own lane, then the enemy lane of the same column, and the lowest-id creep leads a group.
- Creep spawn tiles are the nearest free tiles around the barracks.
- The creep cap check on merge exists but can never fail, because the cap already limits creeps alive to 30.
- Build mode stays on after a placement in both clients (unchanged from the last session).

All of it is written in GDD 9.3 and waits for the owners.
